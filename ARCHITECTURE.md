# oAX architecture

## Current implementation status

As of 2026-10-02 the local preview includes protocol/runtime, persistent editor connections, debounced versioned observations, deterministic TypeScript/JavaScript graph queries, bounded context, optional restricted Codex text, saved-file rename previews, Git history, observed symbol decorations, and an event-driven status bar. The complete platform is unreleased. See PROGRESS for exact verification.

The core is independent of VS Code; provider-specific JSONL RPC remains in `packages/codex`. Public oAX stdio envelopes remain distinct from provider RPC. A random parent-generated token authenticates each private connection; no TCP listener exists. Runtime sessions, grants, and audits are memory-only.

Each session owns its graph and selected-buffer overlay so one session cannot replace another's unsaved context. Indexer discovery enforces exclusions, symlink checks and budgets. TypeScript's checker resolves local relative modules, exports and re-exports and preserves unresolved edges; filename test relationships remain heuristic. SQLite migration 1 has foreign keys, indexes and transactions. Unchanged source/file records are reused; semantic relationships are reconciled globally after changes. Runtime observations and background polling share a serialized refresh queue. Background refresh retains the selected dirty overlay, records refresh errors without claiming freshness, and stops before session graph disposal. `index.status` exposes generation, counts and refresh state. CLI analysis persists its graph under `.oax`; sessions do not persist source excerpts.

Codex selection editing keeps the provider text-only. The runtime validates its untrusted JSON replacement against a saved captured range; the model cannot select another path, create files, invoke tools or grant permissions. The editor presents a native diff, and exact-plan approval reuses the runtime write boundary and baseline checks. Generated changes remain unverified until separately authorized tests run. Rename retains its deterministic semantic validation; arbitrary selection edits make no such claim.

Context includes the captured selection, focused symbol and at most six bounded caller excerpts with source hashes and resolution labels. It does not overlay other unsaved editors. Agent cursor events identify observed graph locations; decoration never moves the human selection. The status bar consumes public events, with no provider reasoning dependency.

External text is explicit opt-in, pinned to Codex 0.159.2, with verified disabled environment/tool configuration and process-only MCP overrides. Runtime context approval is hash-bound and checked at engine execution. Unsupported versions/configuration fail closed. See docs/codex-integration.md. Live provider tools remain unavailable.

Rename plans are generated by the TypeScript language service over indexed snapshots. Only saved ordinary files can be written; exact preview approval, expiration, baseline hashes, resource grants and file identity checks gate execution. Rename syntax is checked before approval; model selection proposals are separately labeled unverified. Writes are not a multi-file atomic transaction; partial failures report affected files and do not promise rollback. Separate saved Node-test plans enforce exact-operation approval, source freshness, bounded output, timeout and actual exit status. Multi-file model edits and file creation/deletion remain pending. Local Git history uses fixed read-only subprocess commands, with no hooks/pagers/text conversion or remote operations. Historical evidence is not treated as proof of intent.

VSIX packaging uses an allowlisted staging directory and two bundles; the CLI currently runs from a built checkout. This is a local development preview, not a public Marketplace or npm release. Optional Chrome DevTools inspection is implemented as a separate CLI adapter. Broader GitHub issue/review/check integration, richer Buddy/voice, additional adapters and team/deployment surfaces remain design work.

## Architectural direction

oAX is the context and interaction layer; Codex is its primary agent engine. The core runtime is independent of editor APIs and provider wire protocols. The first deployment is local, with a VS Code adapter and CLI.

## Proposed module boundaries

| Location               | Responsibility                                        | Boundary                                      |
| ---------------------- | ----------------------------------------------------- | --------------------------------------------- |
| `packages/protocol`    | Messages, commands, events, types, JSON schemas       | No editor or provider dependency              |
| `packages/runtime`     | Sessions, tasks, lifecycle, orchestration             | Coordinates injected services                 |
| `packages/context`     | Relevance selection and bounded ContextSlice          | Records provenance and freshness              |
| `packages/spatial`     | Latest editor state and version tracking              | Uses protocol types, no VS Code API           |
| `packages/codegraph`   | Symbols, relationships, graph queries                 | Deterministic evidence and confidence         |
| `packages/permissions` | Policies, scoped grants, enforcement, audit           | Required at every action boundary             |
| `packages/codex`       | AgentEngine implementation and provider transport     | Only provider-specific boundary               |
| `packages/git`         | Local history, blame, commit evidence                 | Read operations separated from mutations      |
| `packages/github`      | Authorized PR, issue, and review context              | Least-privilege remote access                 |
| `adapters/vscode`      | Editor observations, commands, decorations, approvals | No model orchestration logic                  |
| `apps/cli`             | Initialization, analysis, and local runtime commands  | Uses shared core services                     |
| `services/indexer`     | Discovery, parsing, symbol extraction                 | Honors exclusions and supported languages     |
| `services/watcher`     | Incremental updates and invalidation                  | Handles changes, deletion, and branch changes |

Only create modules needed for the current slice. Placeholder directories are not implemented capabilities.

## Explain flow

1. The editor adapter captures workspace identity, document URI/version, selection, and visible ranges.
2. The runtime validates the message and associates it with the session.
3. Spatial and graph services resolve the selected symbol against the matching document version.
4. The context engine produces a bounded ContextSlice containing relevant files, symbols, graph paths, and available history with provenance.
5. The orchestrator calls AgentEngine with the objective and approved context.
6. The Codex adapter translates supported provider events into oAX events.
7. The IDE displays the answer and supported agent locations. It does not move the user's cursor without a user-enabled behavior.

Unsaved buffers must be represented explicitly. Do not resolve a selection against stale on-disk code without reporting the mismatch.

## Refactor flow and task lifecycle

Proposed task states:

`created → gathering_context → planning → awaiting_approval → executing → verifying → completed`

Failure and cancellation are possible from any active state. Define valid transitions explicitly and test them. A denied approval ends the pending action or permits a revised plan; it must never transition directly to execution.

A refactor gathers impact context, produces a reviewable plan, obtains scoped authorization, performs permitted edits, runs authorized checks, and presents the diff and evidence. Failures preserve diagnostic results. Cancellation must stop pending work and release resources; it does not imply automatic rollback of existing edits.

## Protocol v0.1 rules

- Version envelopes and schemas together. Validate all inbound messages.
- Use discriminated request, response, event, and notification variants; document whether a response is success or structured error.
- Include unique message IDs, correlation IDs, timestamps, workspace/session scope, and ordered sequence numbers where replay requires ordering.
- Use zero-based line/column positions and end-exclusive ranges. Normalize workspace-relative paths; reject paths escaping the workspace.
- Define capability negotiation, unknown-method handling, structured errors, cancellation, timeouts, payload limits, and backpressure before live integration.
- Give agent events task and session identity. Emit UI locations only when supported by observable evidence; never invent precise file positions from prose.

Provider reasoning internals are not required for Buddy. Buddy consumes public status and tool activity events.

## Graph and context storage

SQLite is the initial graph direction. Nodes represent files and symbols; edges represent evidenced relationships. Add commits, PRs, issues, and tests when their integrations exist. Use foreign keys, relationship indexes, transactions, schema migrations, and per-file replacement/invalidation. Stable symbol IDs must account for path and identity changes.

Label unresolved, inferred, and syntactically extracted relationships separately from semantically resolved edges. Tests must cover ambiguous names and incomplete resolution.

Proposed local state lives under `.oax/`: configuration, graph, context metadata, and session records. Context and logs may contain sensitive data; do not commit them by default. Define retention and migrations before depending on persisted sessions.

## Provider boundary

AgentEngine should expose initialization, session creation, streamed execution, interruption, and closure. Use a mock implementation for the first loop. Verify the selected Codex integration's current official protocol and authentication requirements before implementing transport; this document does not pin endpoint names, method shapes, or SDK versions.

A provider adapter must surface connection failure, disconnects, approvals, cancellation, and terminal results. Do not claim runtime policy controls provider tools until every enabled path is enforced or explicitly disabled.

## Added local preview boundaries

Repository onboarding consumes deterministic graph counts, imports, file hashes and root manifest dependency names; entrypoint and test filenames remain heuristics. Optional packages/browser owns the pinned Chrome DevTools MCP client, fixed read-only tool allowlist, origin/page scopes and dedicated profile lifecycle. It is accessed through a separate CLI bundle, outside Codex and editor orchestration. The runtime owns rename/check approval plans and exposes their state through public schemas.

The packages/github fixed-origin GET adapter is initialized only by an explicit approved selected-repository connection. Each runtime session owns its credential and authorization expiration; exact resource grants wrap requests. Editor authentication input and optional SecretStorage remain adapter responsibilities. PR association evidence is returned to the editor without being injected into provider context. Deterministic HTTP fixtures prove boundaries; live authenticated product acceptance is pending.

Spatial capture now derives open files from actual file-backed text tabs, listens to tab/open/close/save events, and compares the complete source-free observation metadata before deduplication. Results from asynchronous observation requests are checked against the current active editor before display. The extension's read-only inspection API reports the accepted metadata and decorated agent location without returning buffer text; it is used for real editor acceptance and does not orchestrate core tasks.
