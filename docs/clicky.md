# Clicky source review and oAX adaptation

The open-source [farzaa/clicky](https://github.com/farzaa/clicky) snapshot is pinned to `a80fa80721a8aebe51a170a7780705024ebc6e46` (MIT, Copyright 2026 Farza). Its upstream README distinguishes this public snapshot from later private development. oAX does not claim access to those private features.

## Reference installation

Run `python scripts/setup-clicky.py` with Python 3.12+. The official archive SHA-256 is `a629892821a7f85122de86cc2a36738f2db7a2befe349e9259ef1f1c7272171b`. The installer verifies the archive, bounds extraction, checks existing file contents and writes 85 source/reference files beneath `.tools/clicky`. Upstream symlink descriptions are inert text. The upstream MIT license stays with the source; no source, credentials, tools or caches are included in oAX packages by this installation. Re-running checks the installation against the archive.

This is a reference-source installation. The upstream native application requires macOS 14.2+, Xcode and separately configured transcription/chat/TTS services. It cannot be built or run as a native Windows application here. No upstream worker, analytics, update/release script or model client is launched. The attached archive was inspected separately; the installed reference uses the official pinned archive.

## Features mapped to oAX

| Reviewed Clicky component                                         | Useful concept                                  | oAX implementation or remaining gate                                                                                                                                                                                                                             |
| ----------------------------------------------------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CompanionManager.swift`, `CompanionPanelView.swift`              | Visible activity, a companion the user can hide | Shared `BuddyStore` now also drives authenticated workbench/desktop inspection receipts. Hide/show changes presentation only. Agent task status and read receipts remain distinct.                                                                               |
| `OverlayWindow.swift`, `ElementLocationDetector.swift`            | Point to relevant evidence without taking focus | Existing VS Code cursor uses runtime locations validated against document hashes/versions. Workbench explicitly shows no agent location until a supported agent workflow exists; model-generated screen coordinates are not imported as proven source locations. |
| `BuddyDictationManager.swift`, `BuddyTranscriptionProvider.swift` | Push-to-talk and provider separation            | Requested voice input/output remains open. It requires explicit microphone controls, transcript review, cancellation, backend selection and live acceptance. There is no microphone capture in the shipped web or desktop surface.                               |
| `CompanionScreenCaptureUtility.swift`                             | Ground interaction in what the developer sees   | Current editor snapshots and optional origin-scoped Chrome MCP observations provide supported context. Desktop screen capture and screenshot-to-source mapping remain open.                                                                                      |
| `worker/src/index.ts`, speech/chat clients                        | Keep credentials outside UI bundles             | Existing provider adapter and runtime authorization remain authoritative. Clicky's fixed proxy endpoints and third-party subscriptions are not reused.                                                                                                           |

The new workbench companion is an oAX implementation of the interaction concept; Swift application code and assets are not copied into oAX bundles. It displays actual inspection start/completion/failure, ignores superseded completions, preserves the source selection, and cannot grant permissions. Completion means a read returned, not that an agent ran or tests passed. Monotonic presentation revisions prevent delayed polls from reverting a completed receipt to running. Hiding Buddy leaves the underlying operation intact.

Chrome MCP and Jev remain a separate, bounded browser observation/planning path. Installing Clicky does not grant either tool access to personal browser profiles, microphone audio, screen contents or repository writes. Full browser action execution, live TypeSafe planning, voice and native cross-platform overlays remain separately tracked work.
