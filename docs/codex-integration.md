# Codex integration verification — 2026-10-02

Official sources: [App Server](https://learn.chatgpt.com/docs/app-server) and [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference). Exact accepted versions are **codex-cli 0.159.2** and **0.159.0-alpha.12.1**. The installed alpha's generated initialization, thread/turn start, interrupt, configuration, thread, sandbox and user-input contracts were compared with the previous generated contracts and match byte-for-byte. Unknown versions remain rejected; alpha support is an unreleased preview, not a general version range. Wire types/methods are confined to `packages/codex`. PROGRESS records live acceptance separately from contract inspection.

The adapter uses private JSONL stdio, initialize/initialized, account/read without token refresh, config/read, thread/start, turn/start, agent-message notifications, turn/completed, and turn/interrupt. It does not initiate login or read/print credentials. Each provider process uses a disposable empty working directory; threads are ephemeral, read-only with networkAccess false, empty environment and dynamic-tool selections, and no loaded repository instruction sources. Effective configuration must match disabled shell, apps, plugins, hooks, browser, computer, agent, memory, image, and related tool features. Inherited MCP servers are discovered without printing configuration, disabled with process-only overrides, and rechecked. No user configuration is changed.

All provider-originated requests, including tool approvals, fail closed and end the RPC stream. Unexpected tool activity fails the text task. This enables restricted text explanations, not provider workspace tools or general agent editing. It is not an OS isolation guarantee. Provider/model network communication is necessary even though environment networking is disabled.

The runtime previews a bounded ContextSlice and requires approval of its SHA-256 before transmission. The grant binds workspace, principal, session, task, provider capability, exact context hash, and expiration. Missing or changed hashes block engine execution. The editor requires user-level executable configuration and a concrete transmission dialog. Secrets can still occur in normal source excerpts; path exclusions are not comprehensive content redaction.

With explicit user authorization, the synthetic live test passed provider authentication/configuration, model response, process cleanup, and the actual stdio runtime context-consent loop. Missing consent was denied. Deterministic tests cover correlated RPC, server request denial, timeout/disconnect, and context-hash mismatch. The installed VS Code acceptance also passed real production dialogs through a separate excluded development harness. Normal tests use mocks. Use `pnpm test:live` only with explicit opt-in and disclosure; each newly accepted executable still needs recorded live acceptance.

Limits include supported-version rejection, 10-second RPC requests, 16-KiB provider input, 60-second turn timeout, 64-KiB text output, and bounded RPC queues. Windows cleanup waits for process close before removing the created temporary directory. No provider reasoning content is exposed to Buddy or the editor.
