# Historical evidence

Select saved, tracked code and run **Show Git History Evidence**. The runtime validates the document/disk snapshot, scopes a Git read grant, and returns HEAD, up to fifty local/remote branch names, selected-file status and diff, ten file-history commits and at most five selected-line origin commits from blame. Uncommitted selected lines do not invent an origin commit. HEAD and selected-file changes during retrieval cause a retry error. Displayed blame/diff and commit subjects are bounded. No shell, external diff, text conversion, network or mutation is used; optional Git index locks are disabled.

**Connect Read-Only GitHub Evidence** verifies an explicitly approved repository token. Request metadata, contents, pull requests, issues and checks read permissions for only that repository; unavailable API permissions are reported. Credentials stay in session memory unless the user chooses VS Code secret storage. VS Code sign-in and chat connectors are separate from this product connection. OAuth sign-in and GitHub Apps are not implemented.

**Show Associated GitHub PR Evidence** traces the first selected blame commit, rather than the newest file commit. It retrieves five PR associations and check runs, discussions for two PRs, five reviews and timeline comments per PR, and two same-repository issue references per PR. These are bounded first pages; additional records may exist. Issue references are textual heuristics, not proof of causal intent or verified closing relationships. URLs for PRs/issues are constructed from the approved repository and numeric identity. Redirects and provider transmission are disabled. Partial API failures produce explicit unavailable-route records. The private request timeout accommodates bounded serial reads.

Every GET has an exact repository/session/resource grant. `git.read`, `git.write`, `github.read` and `github.write` are distinct capabilities; read authorization never permits posting, pushing, merging or changing access. No Git/GitHub mutation method is exposed. This development agent's authorized GitHub sync is separate from product capabilities.

Acceptance uses real Git repositories and the real stdio runtime, plus deterministic HTTP fixtures for GitHub. Provenance quality scenarios cover an unrelated newer file commit, uncommitted selected lines, deduplicated issue references, review/check evidence, credential redaction and denied write escalation. The actual oAX repository is also traced through its selected `offset` declaration. These evaluate evidence correctness and attribution; they do not measure a live model's historical narrative quality. Live authenticated product GitHub/UI acceptance remains pending a configured product connection. This is not a public release.

Provider contracts follow the official [pull-request API](https://docs.github.com/en/rest/pulls/pulls), [reviews API](https://docs.github.com/en/rest/pulls/reviews?apiVersion=2026-03-10) and [check-runs API](https://docs.github.com/en/rest/checks/runs).
